## 結論を先に

- **候補（ema-cross-v1 の上向き・自信上限のときだけ買う・指値・ロングだけ）は、valid で平均がマイナスだった。** 5銘柄 pooled で -0.162%/回（t -0.34）、next_open なら -0.376%（t -0.77）。btc+eth だけなら +0.211%（n=87、t +0.35）で、ゼロと区別がつかない。目的（手数料を引いた後の平均が本当にプラス）は満たしていない。
- **約定の側の寄与だけは、信号に依らず、train でも valid でも同じ大きさで残った。**
  - 指値（メイカー受取、すべり0）は成行より **1回あたり +0.21〜+0.25%**。5銘柄で base +0.344、smin2 +0.231、long +0.249、always_long +0.252（train）、valid では B +0.214、A +0.216、always_long +0.228。手数料 0.36% を浮かせて、逆選択（指値は不利な方向に動いたときだけ約定する）で 0.08〜0.13% を失う差し引き。
  - ショートをやめる寄与は **train +0.60%、valid +0.45%**（A と B の差）。valid のショートは net -0.93%/回（limit）。上げ相場の train だけでなく、valid でもショートが足を引いた。
  - hold_through は平均を上げるが sd も上がり、mean/sd は動かない。指値ならコストが無いので建て直しの損がそもそも小さい。使わない。
  - ボラでサイズを揃える（invvol）は銘柄ごとの sd を揃えるだけで mean/sd は上がらない（roc の t 2.62→2.54）。使わない。
- **train で見えた優位の大半は beta（上げ相場のロング）だった。** always_long+limit が train 5銘柄で t +2.95、valid で -0.93。候補は always_long より mean/sd が高い（train 0.119 対 0.076）が、valid でその差は +0.07%/回しかなく、ゼロと区別がつかない。
- 運だけの基準線（random 50個の train 最良）は next_open で train t 1.39 → valid 0.01、limit で train t 2.33 → valid -0.25。候補の train t（btc+eth 2.19、5銘柄 2.62）はこの線をわずかに超える程度で、valid でランダムと同じところに落ちた。

## 何が残るか（審査への引き継ぎ）

1. **信号（ema-cross-v1）には valid で優位が無い。**ロングだけ・自信上限だけに絞っても gross がゼロ近辺。これは信号側の問題で、約定側では直せない。
2. **約定側の2つは、どの信号に乗せても同じ大きさで効く。** 指値 +0.21〜0.25%/回、ショートをやめる +0.45〜0.60%/回。別の角度で信号が見つかったら、この2つを乗せると必要件数が減る。目安として mean/sd が 0.10 なら required 384、0.15 なら 171。
3. **指値の前提は楽観的。** harness は「次の1時間足の安値が指値を下回れば約定」で、板の順番待ち・部分約定・:05に置く遅れを見ていない。実測しないと本当の差は分からない。本番で「指値を置いた／約定した／しなかった」を記録すれば、この前提そのものを検証できる。
4. **ltc は train・valid の両方でマイナス。**銘柄を増やすなら ltc は外す理由がある。

## 実装の要点（本番＝純 Python、numpy 無し）

- 信号: `strategy.decide()` はそのまま。建てる条件を「`direction == "up"` かつ `confidence >= 0.85`」（strength = |spread|/width >= 2.0）にする。必要な足は SLOW×3 = 144 本と ATR 用 25 本で、いまの7日ぶん（168本）で足りる。計算は 1回あたり 200 回程度の掛け算。
- 約定（仮想）: 2段階にする。run T（足 T-1 が閉じた直後）で建てる条件が立ったら、最後の終値に買い指値を置いたことにして positions.json に `pending` を書く（side, price, placed_at）。run T+1 で足 T の安値が指値を下回っていれば約定（建て値＝指値、手数料 -0.02%、すべり 0）。下回っていなければ取り消し、その run の信号で置き直す。
- 手仕舞い: 建てた足から H=72 本後の足の1本前が閉じたら、その終値に売り指値を置く。次の足の高値が指値を上回れば約定（-0.02%）。上回らなければ、その次の足の始値で成行（0.12%+0.05%）。
- ショートは建てない。建玉管理料の計算と JST 0:00 の判定は不要になる。
- 記録: predictions.jsonl は「none」が増える（train の見送り率は約 8% から、ロング・自信上限に絞ると大半が none）。的中率の欄は判定件数が減る。
- 変えるファイル: run.py（建てる条件、pending の処理）、paper.py（メイカー手数料と指値の約定規則）、positions.json の形。strategy.py は MODEL 名だけ変える。1時間以内に書ける量。

## 危険

- valid で平均がマイナス。y4（2025-09〜2026-03）は -1.08%/回、t -1.79。下げ相場ではロングだけの順張りは負け続ける。
- 指値の約定モデルの楽観（上記3）。メイカー手数料 -0.02% は bitbank の料率改定で消えうる。
- 1回あたりの sd が 5〜8% で、mean/sd 0.10 でも 400 件近く要る。btc+eth だけなら年 90 件前後で、関門まで 4 年以上かかる。
- 「上か下か」を言うサイトで、下を一度も言わなくなる。
