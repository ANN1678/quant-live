# 基準線（baseline）

候補モデルが越えなければならない線を、harness で測った。設計はしていない。
実行: `baseline_run.py` と `baseline_extra.py`（同じ research/ 直下）。生の出力は `design/baseline_run.log`、数値は `design/baseline.json`。
条件はすべて H=72、fill='next_open'、DEFAULT_COSTS（テイカー0.12%＋すべり0.05%を片道、ショートに建玉管理料0.04%/日）、position=0.10。
`lookahead_check(ema_cross_v1, "btc_jpy")` は True。

## 1. データ探索の基準線 snooping_baseline(n_variants=60, pairs=btc,eth)

ランダムに上下を言う戦略（半分は見送り）を60個 train で試し、いちばん良かったものを valid で測った。

| | 値 |
|---|---|
| best_seed | 45 |
| best_train_t | +1.386（n=592、mean +0.278%、sd 4.88、hit 51.7%） |
| valid_t_of_best | +0.012 |
| valid_mean_of_best | +0.004% |

同じ60個の train の t の分布: 最小 -4.72 / 5% -4.32 / 中央 -1.74 / 95% +0.27 / 最大 +1.39、平均 -1.82、sd 1.39。
t が 1.96 を越えたものは 0個、0 を越えたものは 7個。1回あたりの平均損益の60個平均は -0.371%（1個あたり約593件）。

読み方
- 運だけで train の t は +1.4 まで出る。60個で t=+1.96 は出なかったが、それは1個あたり600件でコストが -0.37% 効いているから。候補が数十個の変種から選ばれたなら、train の t が +1.4 程度では運と区別がつかない。
- 運で選んだ最良は valid で 0 に戻る（mean +0.004%、t 0.01）。候補は valid でこれを**明確に**上回る必要がある。

## 3. 参考: random_signal()（seed=0、毎時必ず上か下を言う）の valid

| 銘柄 | n | mean% | t |
|---|---|---|---|
| btc_jpy | 121 | -0.152 | -0.404 |
| eth_jpy | 121 | -0.424 | -0.654 |
| btc+eth pooled | 242 | -0.288 | -0.769 |
| 5銘柄 pooled | 605 | -0.278 | -1.027 |

seed 0〜9 の10個で btc+eth valid の mean は平均 -0.143%（最小 -0.759、最大 +0.328）。1個の seed の n=242 では標準誤差が約0.37%あるので、seed ごとの差はこの範囲の揺れ。

コストの内訳（seed 0、btc+eth valid、242件、ロング132／ショート110）
- 1件あたりの cost_pct の平均 = **0.3945%**（往復の手数料＋すべり 0.34% ＋ 建玉管理料の平均 0.0545%）
- ショートだけの建玉管理料の平均 = 0.120%（72時間で JST 0:00 を3回またぐ ＝ 0.04%×3）
- 粗損益 gross の平均 = +0.106%、正味 = -0.288%

つまり方向に情報が無い戦略は、1回あたり **約 -0.39%〜-0.40%** を期待値として払う。ロングだけなら -0.34%、ショートだけなら -0.46%。
train の60個平均 -0.371%（見送り半分）も同じ線に乗っている。

## 候補が越える線（まとめ）

1. 1回あたりの平均損益がコスト 0.39〜0.40% を払ってなおプラス（= 粗で +0.4% 以上の情報が要る）
2. train の t は運だけで +1.4 まで出る（60変種）。変種を増やすほどこの線は上がる
3. valid で、運で選んだ最良（mean +0.004%、t +0.01）を明確に上回る
4. いまのモデルは train -0.233% / valid -0.454%、4年とも負、5銘柄 pooled valid t=-1.74。これを下回らないのは当たり前で、目標は 1〜3
